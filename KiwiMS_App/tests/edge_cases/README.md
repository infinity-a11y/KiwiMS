# Edge-case kit

Declarations that each trigger one guard of the conversion: mass ambiguities,
protein-compound complexes, replicates and run limits. Every case runs on one
real kinact/KI series, so the expected values below are what the app shows on
real data. Each case is covered twice:

- **by hand:** upload the listed files in the app and compare with the
  category's README;
- **automatically:** `tests/testthat/test-edge-*.R` runs the same files
  through the app's own functions and checks the same numbers.

| Folder | Topic | Tests |
|---|---|---|
| [baseline](baseline/README.md) | The plain declaration every case is compared against | B0 |
| [mass_ambiguity](mass_ambiguity/README.md) | Interpretations of the declaration one peak cannot tell apart | MA1–MA6 |
| [complexes](complexes/README.md) | Compounds per sample, and the design rules applied per protein-compound complex | CX1–CX4 |
| [replicates](replicates/README.md) | Replicate series, replicate groups and their caps | RP1–RP5 |
| [run_limits](run_limits/README.md) | The sample cap of a run and of a deconvolution | LM1 |

Each folder holds a `generate.R` that writes its test files and a README
covering the implementation, every edge case of the topic and the tests for
it.

## What is in the repository and what is generated

Only scripts and documentation are committed. The test files and the
database are generated on request and git-ignored:

| | Committed | Generated by |
|---|---|---|
| `<category>/*.csv` | no | `<category>/generate.R`, `generate_all.R` |
| `fixture/mlkl_bi8925.db` | no | `fixture/make_fixture.R`, `generate_all.R --fixture` |
| the series itself | `../reference_data/kinact_MLKL_3/peaks.tsv` | a deconvolution of the reference dataset |

The automated tests need none of the generated files: they write a fresh set
of test files to a temporary directory on every run, and read the series from
the committed peak list. So they run on any machine, without the raw data.

## The dataset

MLKL + BI-8925, the reference dataset
[kinact_MLKL_3](../reference_data/README.md): 122 Waters samples named
`2026-09-18_MULI+BI-8925_<conc>_<time>min_R<n>`.

- concentrations 0, 2.5 (`2o5`), 5, 10, 20, 40 and 80 µM, times 1–60 min, two
  replicate series R1 and R2, plus two 0 µM controls at 0 min;
- MLKL 21,638.84 Da and a second form at 21,816.84 Da (+178, likely N-terminal
  gluconoylation, about 21 % of the signal in every sample);
- BI-8925 adds 266 Da.

The conversion reads only the peak list of a result, so the kit runs on the
committed peaks of the series (466 peaks). The manual tests need a database
the app opens: `fixture/mlkl_bi8925.db` (about 800 KB) holds
- all 122 peak lists;
- the spectrum (21,000–22,600 Da), UniDec parameters and error metrics of the
  two samples the manual tests open in the Spectrum view, `2o5_3min_R1` and
  `2o5_1min_R1`. Other samples show no spectrum;
- no logs and no local paths.

Build it with

```
Rscript tests/edge_cases/fixture/make_fixture.R [--from=<result_db>]
```

Without `--from` it deconvolves those two samples from the reference dataset,
which must be present and match its manifest (0.5–1.5 min, needs the
kiwims Python environment). With `--from` it takes them from an existing
deconvolution of kinact_MLKL_3 made with the reference parameters, e.g.
`E:\KF_Testing\Results\KiwiMS_2026-09-28_id6556.db` or a run made in the app.
Either way their peaks are checked against the committed list, so a result of
other data or other settings is refused. Any full result of the series also
works in the app instead of the fixture, with every spectrum.

## Setup for every manual test

1. **Generate the files** (once, and after a generator changed):
   `Rscript tests/edge_cases/generate_all.R --fixture` from `KiwiMS_App`.
2. **Conversion:** load `fixture/mlkl_bi8925.db`. Use **Peak Tolerance 3 Da**,
   **Max. Stoichiometry 4** and **kinact/KI on**, unless a test says
   otherwise.
3. **Proteins tab:** upload the listed `proteins_*.csv` and confirm.
4. **Compounds tab:** upload the listed `compounds_*.csv` and confirm.
5. **Experiment Configuration dialog:** upload the listed `config_*.csv`.
   Then, in the Samples tab, press **Use Experiment Config** (the wand button).
   This fills Protein, Compound 1/2, concentration (µM), time (min) and
   Replicate for all 122 samples.

Files are named by folder: `baseline/proteins_baseline` is
`tests/edge_cases/baseline/proteins_baseline.csv`.

## Conventions

- **Reference sample** `2026-09-18_MULI+BI-8925_2o5_3min_R1`: unbound
  21,638 Da, second form 21,816 Da, complex peak 21,903.5 Da at 17.43 %
  intensity, 12.04 % binding.
- **Window:** two masses can claim the same peak once they are **≤ 2 ×
  tolerance** apart (6 Da at a tolerance of 3). The boundary counts.
- **kinact/KI** values are in M⁻¹s⁻¹: set the Unit View to M and s to read them
  directly (334.1 M⁻¹s⁻¹ = 0.0200 µM⁻¹min⁻¹).
- **Total % binding** comes as two numbers:
  - **Card:** what the Tot. Binding card of the Compound and Protein View
    shows. It is per compound and averages the compound's hit rows, so a
    sample counts once per proteoform and mass shift carrying the compound,
    and samples without a hit of it are left out.
  - **All samples:** the mean over all 122 samples, one value each, 0 % for
    samples without a hit. The app doesn't show it; it is here to compare
    tests.

## Running

From `KiwiMS_App`:

```
# The automated tests (all of them, or one category)
Rscript -e "rhino::test_r()"
Rscript -e "testthat::test_file('tests/testthat/test-edge-replicates.R')"

# Write the files of every category, or one, and print what the app shows
Rscript tests/edge_cases/generate_all.R --report [--fixture[=<result_db>]]
Rscript tests/edge_cases/mass_ambiguity/generate.R --report
```

The `test-edge-*` files take under a minute together, most of it the
kinetics fits. A category's report reads files of the categories before it,
so generate those first (`generate_all.R` keeps the order).

## When a number changes

The expected values pin the current models. When a change to the fitting or
the screening moves them on purpose:

1. run `generate.R --report` for the category and check that the new numbers
   are explained by the change;
2. update the category's README and the `expect_rounded()` values of its
   `test-edge-*.R` together, and say in the README what changed and why.

The 0.7.5-2 merge is an example. It left hits and binding unchanged but moved
every kinetics number: k_obs is now fitted with a free plateau, and kinact/KI
comes from one global fit with a bootstrap CI. The B0 kinact/KI went from
227.6 to 334.1 M⁻¹s⁻¹. kinact/KI is read from the result's `Ratio`, which also
exists when the data don't saturate and kinact and KI are N/A.
